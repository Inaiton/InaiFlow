# Requests to S2 (accounts)

## From S3 (payroll)
1. `accounts.interface.resource_names(db, ctx, "LEDGER", ids)` — please support `LEDGER` (id -> name, org-scoped). Payroll
   settings / mark-paid validate ledger ids with it (system ledgers are already accepted via `get_ledger_ids_by_code`), so
   user-created bank ledgers are rejected (400) until this lands.
2. `post_system_voucher(base_type="PAYROLL", ...)` receives several `DIRECT_WAGES` DR entries with different `cost_centre_id`
   (one per period-run cost centre + one with `None`) — please allow the same ledger more than once per voucher.
   `base_type="PAYMENT"` is used for mark-paid (DR SALARY_PAYABLE / CR bank). Payroll pre-checks balance; amounts are 2 dp.
3. Optional: expose ledger group/nature (e.g. `get_ledger_briefs`) so payroll settings can validate groups strictly.

   - `list_stock_items_out(db, ctx, *, q, target_type, acl: app.core.deps.AclFilter, limit, offset) -> (list[dict], total)` — dicts shaped
     exactly like contract `StockItemOut`; filter with `acl.clause(StockItem.id)`.
   - `get_stock_item_out(db, ctx, item_id) -> dict`, `create_stock_item(db, ctx, body: StockItemIn) -> dict`,
     `update_stock_item(db, ctx, item_id, body: StockItemIn) -> dict` (same rules/audit as `/accounts/stock-items`).
2. Please also export the schema classes `StockItemIn`, `BomComponent`, `KpiOut` from `accounts.interface`; operations uses them when

   `/operations/runs/{id}/linked-vouchers/{voucher_id}`); please keep that working or add `unlink_voucher_from_run(db, ctx, *, voucher_id, run_id)`.
