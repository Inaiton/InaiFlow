# W4 — Admin web decisions

1. **Role map is generated, not hand-written.** `scripts/gen-admin-roles.mjs` (run by `pnpm gen:api`) reads `x-admin-roles` from
   `docs/api/openapi.json` into `src/lib/api/admin-roles.gen.ts`. `adminCan(role, action)` uses it, plus one refinement from plan §3.3:
   lifecycle `ARCHIVE` is SUPERADMIN-only (SUPPORT_ADMIN may ACTIVATE / SUSPEND / EXTEND_TRIAL). Sidebar items, buttons and pages are gated by it.
2. **Token types** come straight from the contract (`TokenOut` collision fixed upstream); the earlier runtime guard was removed.
3. **Auth flow.** Login status is always a challenge (contract has no OK status). `otpauth_uri` present → QR (qrcode → data URL) + manual secret;
   `PASSWORD_CHANGE_REQUIRED` → new password (10–128) + code. Refresh is single-flight (concurrent 401s share one `/admin/auth/refresh`, which
   matters because refresh tokens rotate and reuse revokes the family). Idle logout after 30 min without input. `?next=` only accepts same-origin paths.
4. **Config payload shapes follow `server/app/seeds/*`** (checked against `config_rows()` output): GST `{rates[], cess.modes, thresholds, hsn_digits, rcm_common}`,
   TDS `{sections[], due_day_of_next_month, march_due_date}`, PAYROLL_STATUTORY one config per key (EPF / ESIC / PT_SLABS `{states:{code:{…slabs}}}` /
   INCOME_TAX `{cess_rate, regimes:{NEW,OLD}}`) — the editor detects the part from the payload shape. Seed tables (ACCOUNT_GROUPS, DEFAULT_LEDGERS,
   VOUCHER_TYPES, UOM `uoms`, INDIAN_STATES, ISO_CHECKLIST) use a generic table editor. Every structured editor falls back to the JSON editor when the
   payload does not parse; zod objects are loose so unknown keys survive a round-trip. Strict decimal validation (`^-?\d+(\.\d{1,4})?$`) runs before publish.
5. **Report blocks:** server seeds use `kv` and `qc_table`; the brief said `kv_table` / `qc_readings`. New blocks use the server names; the aliases are
   read and edited as the same block. `checklist` is supported in addition.
6. **Token picker** loads `GET /admin/meta/template-tokens` (lazily, when opened).
7. **QC gate validation** (client, advisory) requires only a PASS branch on DIAMOND nodes; seeds route rejects implicitly via `reject_action`.
8. **Push dialog** shown for template categories (`pushable` in `features/config/categories.ts`); statutory categories get an effective-from date in the publish dialog.
9. **Reasons**: every privileged mutation now sends the typed `reason` (plans, invoices create/status, admin update included).
10. **Cross-feature imports** are limited to public api hooks (`plans/api`, `organizations/api`, `admins/api`); transfer-owner uses `GET /admin/organizations/{org_id}/members` — no shared component code across features.
11. **Charts:** signups sparkline is a hand-rolled SVG over typed `SignupPoint[]`.
12. **Impersonation:** `launch_url` opens in a new tab with `noopener,noreferrer`; the token itself is never displayed or stored; expiry is shown.
13. Versions: TypeScript 5.9 (Next 16 / openapi-typescript peer), ESLint 9 flat config, TanStack Table 8, @xyflow/react 12, vitest 4.
