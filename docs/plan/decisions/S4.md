# S4 — Operations + Documents: decisions & deviations

## Operations
1. **Step counters are cumulative.** `input/accepted/rejected/rework` accumulate over executions (partial batches allowed).
   `pending = input − accepted − rejected − (rework if the node has a REWORK edge)`. Execute requires `pending > 0` and
   `input_qty ≤ pending`; status → ACTIVE while pending, else PASSED (REJECTED if nothing was ever accepted). Rework without a
   REWORK edge stays on the node as pending. Units arriving at a PASSED/LOCKED step re-activate it (lock kept → override needed).
2. **Routing:** accepted → every PASS/DEFAULT target gets `input += accepted` (fan-out = same units on parallel paths);
   rework → REWORK target; rejected → Stock Journal WIP→SCRAP + NCR (AUTO_QC) and, if present, REJECT targets.
   TERMINATOR accepted = committed units: Stock Journal WIP→FG; `run.accepted_qty = Σ terminator accepted`.
   Stock journals are posted only when the run has a stock item (rate = item opening rate).
3. **Diamond criteria:** modes `ALL_FIELDS_IN_TOLERANCE` (alias `ALL_IN_TOLERANCE`, used by seeds), `ACCEPTED_GT_ZERO`, `EXPRESSION`,
   `MANUAL`. If criteria fail, `accepted_qty` must be 0 (400 VALIDATION_ERROR, details `criteria=FAILED`). Expression language:
   numbers, field keys, `accepted|rejected|rework|input`, comparisons, `and/or/not` (`&& || !`), parentheses — recursive-descent
   parser, no eval.
4. **Quick QC:** `quick_qc=true` or an omitted field that has a nominal → nominal value, `auto_filled=true`, `in_tolerance=true`;
   BOOL fields auto-fill `true` only with `quick_qc`. `step.quick_qc` is true when anything was auto-filled. Required fields still
   missing (no nominal) → 400 unless quick QC.
5. **Skip** not allowed on TERMINATOR (commit) or `skippable=false`. **Succeed** accepts all pending with nominal readings
   (criteria not evaluated; audited EXECUTE with reason). On a locked step, `succeed` reason doubles as override reason.
6. **Signoff** allowed on any non-PENDING step; DIAMOND with nothing pending → status LOCKED. **Reopen** (FULL + reason)
   unlocks and clears signer; audit OVERRIDE.
7. **Complete** requires every step that received input to be PASSED/SKIPPED/LOCKED/**REJECTED** with nothing pending (a fully
   rejected gate is terminal). Manufacturing journal (MFG_JOURNAL): CR STOCK_RM = Σ BOM `qty_per_unit × planned × (1+scrap%)` ×
   raw opening rate (OUTWARD MAIN), DR STOCK_FG = accepted × unit cost, difference to MFG_OVERHEAD. Skipped without stock item.
8. **Money flow:** debits = vouchers from `accounts.list_vouchers_for_run` (except SALES/RECEIPT → credits; STOCK_JOURNAL,
   MFG_JOURNAL, PAYROLL, orders, memorandum excluded; CANCELLED excluded) + run-page DR postings + PAYROLL allocations; credits =
   CR postings + sales/receipts. `unit_cost = net / run.accepted_qty`. Persisted to `total_debit_cost/total_credit_recovery/
   computed_unit_cost` on every money mutation. New table **`period_run_cost_lines`** (migration 0004) stores postings and payroll
   allocations. Postings use base type JOURNAL (run ledger entry carries the run cost centre).
9. **NCR numbers** `NCR-YYYY-####` from `org_sequences` key `NCR-YYYY` (resets yearly). Manual PATCH may set OPEN/IN_PROGRESS/
   UNDER_VERIFICATION; CLOSED only via `/close` (FULL).
10. **Calibration** status computed live (EXPIRED < today, DUE_SOON ≤ 30 days) and persisted on write; cron keeps using
    `refresh_calibration_statuses` (window changed 15 → 30 days per S4 brief).
11. **Record ACL scoping:** an external collaborator holding READ grants of a resource type sees ONLY granted records of that type
    (grants scope, they don't add). Runs are visible to scoped externals when the run or its stock item is granted. Auditor invites
    create USER grants applied on acceptance (via `organization.invite_member`), role AUDITOR, expiry required.
12. Readiness: per top-level clause (4–10); NOT_APPLICABLE excluded from the denominator.
13. Dossier: PDF draws the executed flowchart as an SVG vector image (layered left→right, taken edges thick terracotta, REWORK/REJECT
    dashed, nodes tinted by status); DOCX gets an edge table instead (python-docx can't embed SVG). `save=true` files it in the run
    folder as `GENERATED_REPORT`.
14. Items facade needs stock-item CRUD/list from accounts (requested, see requests/S2.md); stats/workflow_count are computed here.
15. Shared contract models owned elsewhere (`StockItemIn`, `BomComponent`, `KpiOut`, `InvitationOut`) are taken from the owner's
    interface when exported, else identical copies in `operations/_shared.py` (identical schemas merge in OpenAPI).

## Documents
16. **Folder ACL inherits down the tree** (nearest ancestor override wins). Scoped externals see granted subtrees as top-level roots.
    Documents inherit their folder's level; lists/search filter out invisible folders.
17. Folder names: 1–200 chars, no `/ \` or control chars, unique per parent **case-insensitively** (409 ALREADY_EXISTS). Moves into
    own subtree → 409 CONFLICT. Subfolders may be created inside locked system folders. Run folders are system-locked
    (`system_kind=RUN`), name de-duplicated with ` (n)`.
18. Upload completion is idempotent (READY returns as-is); size mismatch / missing object → 409 UPLOAD_INCOMPLETE.
19. Editing: `rich_content` and `iso_doc_number` only in DRAFT (409 DOCUMENT_LOCKED); title/folder may change anytime.
    Delete: FULL, not APPROVED/OBSOLETE, not linked to a voucher or step; storage object removed unless shared by a revision.
20. ISO lifecycle: DRAFT→UNDER_REVIEW (editor WRITE, file READY); review (iso_approval WRITE, reviewer ≠ preparer);
    UNDER_REVIEW→APPROVED (iso_approval FULL, approver ≠ preparer, reviewed); UNDER_REVIEW→DRAFT (iso_approval WRITE, comment
    required); APPROVED→OBSOLETE (FULL). Approval obsoletes other APPROVED docs of the same revision chain / iso_doc_number in the same
    transaction, each audited. Revise only from APPROVED, one open revision per chain; revisions share the storage object until a new
    file is uploaded.
21. Template tokens are served with braces (`{{org.legal_name}}`) via `documents.interface.template_tokens()`, also used by
    `/admin/meta/template-tokens`. Known-but-empty tokens warn "No value for … in this context"; unknown tokens warn "Unknown token".
22. Superadmin push helpers (requests/S4.md): `operations.install_platform_workflow_template`, `documents.upsert_platform_doc_template`,
    `documents.apply_monthly_folder_rule` (keeps `custom`).
