# S2 — Accounts + Taxation: decisions & deviations

1. **No schema changes**: `0002_accounts` stays a no-op; all needed columns already existed (S1 models).
2. **Balances** use REGULAR vouchers of `is_accounting` types only. **Stock** uses REGULAR vouchers of every type except
   orders / memorandum / reversing journal / attendance (so non-accounting Stock Journals move stock). Opening stock sits in MAIN.
3. **Voucher rules**: ΣDR==ΣCR; ≥2 entries for accounting types (non-accounting may have 0); same ledger may repeat
   (payroll); dates ≥ books_beginning_from and ≤ current FY end (POST_DATED: next FY end); `books_locked_until` checked on
   new and old date (edit/cancel) → 423. Numbers always server-allocated under `SELECT … FOR UPDATE` on `voucher_types`
   (`numbering_method` accepts AUTOMATIC only — VoucherIn has no number field). MEMORANDUM base type forces status MEMORANDUM.
   Edits update entries in place when (ledger, side, amount) match so bank reconciliation survives; `edit_reason` optional, stored as audit reason.
   Cancel also un-matches bank statement lines.
4. **GST metadata** is snapshotted on save for SALES/PURCHASE/CREDIT_NOTE/DEBIT_NOTE (place of supply, split, posted tax per
   head, rate/HSN breakup from inventory lines or ledger `tax_config.rate`, else effective rate). Returns use posted tax
   ledgers (`tax_config.gst_head`) as truth; validator reports breakup vs posted mismatches. Cess needs a user ledger with gst_head CESS.
5. **compute-tax** party side: SALES/DEBIT_NOTE DR, PURCHASE/CREDIT_NOTE CR; RCM → tax on RCM_PAYABLE, not charged to party;
   COMPOSITION/UNREGISTERED orgs charge no outward tax (warning).
6. **Reports**: P&L/BS closing stock = inventory valuation; BS shows cumulative profit since books beginning under
   Shareholders' Funds and a "Difference in Opening Balances" row (ledger openings + opening stock) so it always ties.
   Duties & Taxes (incl. input GST) stay under Current Liabilities (Tally grouping). Cash flow indirect; depreciation =
   indirect-expense ledgers named "*depreci*". Ageing by bill date; MSME flag = payable bill > 45 days for parties with `msme_type`.
   Outstanding bills: NEW_REF/ADVANCE/AGAINST_REF honoured, unallocated amounts knocked off FIFO.
7. **Batch costing** uses `operations.interface.list_runs_for_costing` + `get_runs_by_ids`; cost = cost-centre entries of the
   run (DR−CR) + linked vouchers' expense DR / income CR.
8. **Taxation** reads vouchers only via `accounts.interface.list_vouchers_full` (party tax_config = deductee tag, never a TDS ledger).
   GSTR-1/3B API JSON uses decimal strings; export files are GSTN JSON with plain numbers (rendered from Decimal).
   AATO for the HSN 4/6-digit rule = `accounts_settings.aato` else FY-to-date taxable sales. GSTR-2B import stores normalised
   invoices only. TDS YTD = party vouchers' expense DR (TCS: income CR) in the FY; "deposited" = DR on TDS ledgers by the
   challan due date covers cumulative deductions. 26Q/27Q/27EQ = pipe-delimited FH/BH/CD/DD approximation (not FVU-validated);
   quarter format `2026-Q1` / `2026-27-Q1` (FY quarters). e-Invoice cancel does not enforce the 24h IRP window (gateway does).
9. **Audit**: all mutations write module `ACCOUNTS` (taxation included); exports write `EXPORT`.
10. **Bank CSV** column aliases can be extended via `accounts_settings.bank_csv_columns` ({field: [header names]}); files ≤ 5 MB;
    duplicates by sha256(ledger, date, amounts, ref, description).
11. Edited S3/S4 tests at the lead's request only to drop xfail markers that now pass.
