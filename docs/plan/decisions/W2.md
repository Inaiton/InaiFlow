# W2 — User web Accounts: decisions

| # | Decision | Why |
|---|---|---|
| 1 | Accounts chrome = `app/(tenant)/o/[orgSlug]/accounts/layout.tsx` → `AccountsLayout`: AccBar (Alt+K/Y/Z/O/E/P, F1) on top, F-key RBar on the right (xl+), shortcut scope `accounts`. Screens replace the RBar with `useRBar(items, scope)`; handlers are read at press time via a ref, the bar re-renders only when labels/keys change. | One source for visible keys + registered shortcuts; no stale closures. |
| 2 | Voucher entry is one screen for every base type (`lib/voucher-kinds.ts`): accounting Dr/Cr grid, invoice (party + items + GST via `compute-tax`), inventory (consumption/production). Orders/notes reuse invoice mode with `entries: []`. Stock/Mfg/Physical stock journals send `entries: []` and let the server post stock ledgers. | Contract `VoucherIn` covers all; server owns valuation. |
| 3 | Draft is a pure reducer (`vouchers/entry/draft.ts`) + builder (`build.ts`), both unit-tested. Leaving the last line's amount adds a pre-filled balancing line (Tally). Invoice entries = `suggested_entries` from compute-tax (debounced 350 ms), then TDS (`applyTds`) and party bill allocation applied client-side. | Keeps tax maths on the server; client only arranges entries. |
| 4 | Party bill-wise default on invoices: `NEW_REF` named by supplier bill no. (purchase) or the *expected* voucher number (`prefix+next_number`), due = date + party credit days. | Number is only allocated on save. `// shortcut`: server could default the ref. |
| 5 | Editing an invoice rebuilds the draft from `VoucherOut`; the sales/purchase ledger is the largest entry opposite the party; charge-ledger lines are not reconstructed. Edit reason is asked in a confirm dialog. | `VoucherOut` doesn't mark entry roles. |
| 6 | Enter-to-advance through `[data-nav]` fields; `TypeaheadPicker` (own ARIA combobox) lets Enter bubble after picking, Alt+C creates a ledger/item inline. Dialogs mount `useDialogGuard()` (top "dialog" scope swallowing Esc/Ctrl+A/Alt+C) so the voucher underneath doesn't quit/save. | W1 Combobox is click-first; registry has no "disable lower scopes". |
| 7 | Attach bill after save: walk `/documents/folders` root → FY → month (`month_date`) → `system_kind=BILLS`, then upload-url → PUT → complete-upload → `/vouchers/{id}/attachments`. Failure leaves the voucher saved and toasts. | Contract has no "folder for date" lookup. |
| 8 | Report period lives in `?from=&to=` (default FY start → today); F2 opens the period dialog; drill-down links carry the period. GST screens use a month picker; TDS returns use FY quarters `YYYY-Qn`. | Shareable URLs, back button keeps context. |
| 9 | Contract `json[]` payloads (GSTR-1 sections, GSTR-3B, challan by_section) render through a generic `JsonTable` (columns = union of keys, money columns by key name). | Shapes aren't typed in the contract. |
| 10 | Printable view renders the bill from `VoucherOut` + `/organization/profile` (only when `organization.profile:READ`, else `/org/context` name/logo) + invoice settings; "Print" opens the server PDF. | Real PDF is the server's job. |
| 11 | Chart geometry and meters convert scaled BigInt to Number (`percentOf`, `CashFlowChart`) — display only, never money maths. | Plan §3.1. |
| 12 | Server enum strings used (checked in server code): BRS `show` = unreconciled/reconciled/all, e-invoice `kind` = IRN/EWAY, statutory = epf-ecr/esic/pt, TB `mode` = grouped/ledger, ageing `kind` = RECEIVABLE/PAYABLE, working days = CALENDAR/FIXED_26/FIXED_30. | Contract types them as `str`. |
